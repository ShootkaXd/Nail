# Безопасность

Применённые практики защиты (по мотивам Anthropic Cybersecurity Skills).

## Аутентификация и авторизация
- **JWT** с обязательным секретом — сервер не стартует без `JWT_SECRET` (см. `config/env.ts`).
- **bcrypt** с cost factor 12 для хэширования паролей (админы/setup); пароли никогда не возвращаются в API.
- **Политика паролей**: минимум 8 символов, обязательно буква и цифра (`lib/validation.ts`).
- **RBAC**: middleware `requireRole('admin'|'master')` на каждом защищённом маршруте.
- Нельзя удалить себя или последнего администратора.
- Setup-эндпоинт самоблокируется после создания первого админа.

## Защита от атак
- **Rate limiting** (`express-rate-limit`):
  - вход/регистрация — 10 запросов / 15 мин (анти-брутфорс);
  - создание записи — 8 / мин (анти-спам);
  - общий API — 300 / мин.
- **Валидация входных данных** через `zod` на всех мутациях — отсекает некорректные и вредоносные payload'ы.
- **SQL-инъекции**: исключены за счёт Prisma (параметризованные запросы).
- **XSS**: React экранирует вывод по умолчанию; `dangerouslySetInnerHTML` не используется.
- **Лимит размера тела** запроса — 100 КБ.
- **CORS** ограничен списком origin'ов из `CORS_ORIGIN` (в проде — ваш домен).

## Заголовки безопасности
- `helmet` на бэкенде; nginx добавляет `X-Frame-Options`, `X-Content-Type-Options`,
  `Referrer-Policy`, `X-XSS-Protection`.
- `x-powered-by` отключён.
- `trust proxy` включён для корректной работы rate-limit за обратным прокси.

## Инфраструктура
- Docker: бэкенд работает под **non-root** пользователем.
- Секреты только через переменные окружения, `.env` в `.gitignore`.
- Многоступенчатая сборка — в финальном образе нет dev-зависимостей и исходников TS.

## Рекомендации для продакшена
1. Сгенерируйте сильный `JWT_SECRET`: `openssl rand -hex 32`.
2. Поставьте HTTPS (Let's Encrypt / reverse proxy) — куки и токены только по TLS.
3. Ограничьте `CORS_ORIGIN` вашим доменом.
4. Регулярно обновляйтесь через `update.sh` (применяет и security-патчи зависимостей).
5. Делайте бэкап volume `db-data`.
